# Sign Bridge 웹 대시보드 (역할 4)

AI Hand 5대를 중앙에서 관제하고, 지문자 표현과 학습 과정을 실시간으로 보여 주는 웹 대시보드입니다.
지금은 **가짜 데이터**로 동작합니다. 중앙 PC(FastAPI)가 아래 메시지 형식으로 WebSocket을 열면 그대로 진짜 데이터로 바뀝니다.

## 실행

```bash
cd dashboard
npm install
npm run dev        # http://localhost:5173
npm test           # 자모 분해·통계 계산 테스트
npm run build      # dist/ 에 배포용 파일
```

진짜 서버에 연결할 때는 주소 뒤에 `?ws=` 를 붙입니다: `http://localhost:5173/?ws=ws://PC주소:8765#/`
사이드바 아래 표시가 `가짜 데이터` → `PC 연결됨`으로 바뀝니다.

- 음성 입력은 크롬에서만 되고 인터넷이 필요합니다.
- 카메라와 마이크는 `localhost`나 `https`에서만 권한을 받을 수 있습니다.
- Tailwind는 v3(PostCSS)을 씁니다. v4의 네이티브 스캐너는 이 PC의 Windows 앱 제어 정책에 막혀서 스타일이 생성되지 않았습니다.

## 각도표 반영하기 (이정민 님 양식 · 이기태 님 확인)

손 배치·맡는 손·서보 각도는 모두 드라이브의 **`각도표_양식.xlsx`**(이정민 님 양식)에서 옵니다. 이기태 님이 실제 손으로 채운 파일을 받으면:

```bash
cd dashboard
npm run angles -- "각도표_양식.xlsx"   # "각도표" 탭 + "손 배치" 탭을 읽어 src/lib/angleTable.data.js 생성
npm test && npm run build
```

커밋·푸시하면 GitHub Pages로 자동 배포되고, 브라우저에 저장된 예전 각도표 대신 새 각도표가 쓰입니다.

**구글 시트로 바로 고치기 (코드 없이)**: `src/lib/angleTable.js`의 `SHEET_URL`에 각도표 구글 시트 주소(각도표 탭을 연 주소창 그대로, `#gid=` 포함)를 한 번 넣고 배포하면, 그 뒤로는 시트만 고치고 대시보드를 새로고침하면 반영됩니다.
- 시트 공유를 **링크가 있는 모든 사용자 - 뷰어**로 해야 브라우저가 읽을 수 있습니다(대시보드가 공개 페이지라 주소를 아는 사람은 시트를 볼 수 있음).
- xlsx는 드라이브에서 **Google 스프레드시트로 저장**한 것이어야 합니다.
- 못 읽으면 설정 화면 각도표 옆에 빨간 글씨로 이유가 나오고, 위의 xlsx 각도표를 씁니다.
- 대시보드 화면과 블루투스 테스트 각도만 바뀝니다. 중계기로 움직이는 손의 각도는 이정민 님 `hand.ts`에 있어서 따로 옮겨야 합니다.

- 열은 머리줄 이름으로 찾습니다 (글자, 손 방향, 앞면, 맡는 손, 서보1~6, 상태, 확인한 사람, 메모). 열 순서가 바뀌어도 괜찮아요.
- 맡는 손 `1,2` → 두 손이 **번갈아** 맡음. `없음(화면 안내)`이거나 메모에 `화면 안내`가 있으면 손 대신 화면으로 보여 줌 (지금 ㅁ ㅍ ㅓ ㅔ).
- 서보 기준(양식): 엄지 펴짐 90 / 굽힘 180, 나머지 손가락 펴짐 90 / 굽힘 0, 손목 90 고정. 손등이 보이는 글자는 손을 받침대에 뒤돌려 세움.
- 설정 화면에서 고친 각도는 그 브라우저에만 남습니다(현장 확인용). 확정 값은 xlsx에 적어 주세요.

## 이정민 님 중앙 프로그램과 연결 (시연·통합용)

손 제어와 인식은 이정민 님 `control/`(hand_assign, hand_link, one_loop)이 맡고, 대시보드는 화면만 맡습니다. 둘은 [`bridge/dashboard_bridge.py`](../bridge/dashboard_bridge.py)로 이어요. 이정민 님 파일은 고치지 않고 함수만 불러 씁니다.

```
대시보드(브라우저) ⇄ WebSocket ⇄ dashboard_bridge.py ⇄ control/ (plan_word · HandLink · CamJudge)
                                                     ⇄ 중계 micro:bit(USB) → 무선 → 손 5대
```

1. `dashboard_bridge.py`를 `14조_AiHand_프로그램/control/` 폴더에 넣기 (recognition 폴더와 나란히)
2. recognition/.venv 파이썬에 `pip install websockets pyserial`
3. 실행
   - `python dashboard_bridge.py --fake --sim` : 손·웹캠 없이 흐름만
   - `python dashboard_bridge.py --fake` : 가짜 손 + 실제 웹캠 인식
   - `python dashboard_bridge.py` : 실제 중계 micro:bit(자동으로 찾음, 또는 `--port COM5`) + 웹캠
4. 대시보드를 `https://ranma0831-lang.github.io/aihand-sign-bridge/?ws=ws://localhost:8765` 로 열기 → 사이드바가 `PC 연결됨`

- 연결되면 손 5대에 `펼침`을 보내 받음 응답으로 연결 상태를 표시합니다.
- 표현·학습 시범·테스트·칭찬은 중계 micro:bit로 보내고, 손의 `동작 끝` 응답을 받은 뒤 다음 글자로 넘어가요.
- 학습·도전의 따라 하기는 PC의 웹캠 창(CamJudge, 글자/숫자 모드)으로 인식하고, 결과만 대시보드로 옵니다. 이때 브라우저는 카메라를 켜지 않아요 (한 카메라를 두 프로그램이 같이 못 씀).
- 단어 나누기와 손 고르기는 대시보드와 control이 같은 규칙입니다(30개 단어로 비교 확인): 쌍자음은 기본 자음 + 움직임, ㅘ→ㅗㅏ, 숫자 1~10만, "1,2" 손은 가장 오래 쉰 손.

## 테스트용 직접 연결 (블루투스)

시연·통합 때는 **이정민 님 중앙 프로그램**이 중계 micro:bit로 손 5대를 움직입니다. 아래는 각도를 실제 손으로 확인할 때만 쓰는 테스트용 연결이에요. 대시보드가 중앙 프로그램(`?ws=`)에 연결되어 있으면 대시보드는 손에 직접 명령을 보내지 않습니다.

1. makecode.microbit.org → 새 프로젝트 → Extensions: `https://github.com/Hiwonder/StartbitV2`, `bluetooth` 추가 → 프로젝트 설정에서 `No Pairing Required` 켜기
2. **JavaScript** 탭에 [`firmware/aihand-receiver.ts`](../firmware/aihand-receiver.ts)를 붙여 넣고 Download
3. 확장 보드 전원 **ON** → 대시보드 **개별 제어** → 아래 **"테스트용 직접 연결"** 펼치기 → 손 번호 → `BBC micro:bit` 선택 → ♥
4. 손 카드에서 글자를 골라 `테스트`

보내는 형식: `서보1,서보2,서보3,서보4,서보5,서보6,시간ms$`

## 화면 (기획안 번호)

| 화면 | 주소 | 내용 |
|---|---|---|
| ① 통합 관제 (관리자) | `#/admin` | 손 5대 연결·방향·역할·상태(대기/실행/완료/오류), 지금 손과 글자, 전체 진행률, 다음 손, 시스템 시작/정지 |
| ② 지문자 표현 (첫 화면) | `#/` | 텍스트·음성 입력, 시연용 예시 단어 버튼, 자모 분해와 담당 손 미리보기, 지금 글자 강조, 다음 글자, 표현 불가 글자는 영상·사진 팝업, 시작/일시정지/재개/중지 |
| ③ 학습 | `#/learn` | 글자 선택 → 시범 → 웹캠 → 정답/오답·정확도, 오답이면 시범 다시, 정답이면 칭찬 동작, 연속 정답·진행률 |
| 지문자 표 | `#/chart` | 자음 14·모음 17·숫자 1~15 손 그림(국립장애인도서관), 누르면 크게 보기, 글자마다 맡는 손/화면 안내 표시 |
| ④ 개별 제어 | `#/robots` | 손별 상태, 각도표의 목표 각도, 테스트 전송과 결과, 오류 해제, 긴급 정지, 테스트용 블루투스 직접 연결 |
| ⑤ 통계 | `#/analytics` | 표현 횟수, 인식률(N-02), 피드백 시간(N-03), 음성 정확도(N-04), 학습 성공률(S-09), 오류, 날짜별 그래프, 글자별 정답률, 전체 기록 |
| ⑥ 설정 | `#/settings` | 손 배치(방향·앞면), 각도표(양식 그대로, 확인됨 개수), 동작 속도, 카메라·음성, JSON 내보내기/불러오기 |

메뉴는 사용자용(표현·학습·도전·사용법)과 관리자용(통합 관제·개별 제어·통계·설정)으로 나뉘고, 메뉴 아래 `관리자 모드` / `사용자 화면으로` 버튼으로 바꿉니다.
긴급 정지는 모든 화면의 사이드바(휴대폰에서는 위쪽)에 있습니다.

## 메시지 형식 (WebSocket, JSON)

### 대시보드 → 중앙 PC
| 메시지 | 언제 |
|---|---|
| `{"type":"express","word":"사랑","plan":[{"jamo":"ㅅ","hand":4,"angles":[135,90,90,0,0,90]},…],"stepMs":1200,"gapMs":250}` | 표현 시작. `hand:null`이면 화면 그림으로 대체하는 글자 |
| `{"type":"demo","jamo":"ㄱ","hand":1,"angles":[…]}` | 학습 시범 |
| `{"type":"recognize","jamo":"ㄱ","mode":"글자"}` | 사용자 손 인식 시작. `mode`는 `글자`/`숫자` (인식 모델 `predict_in_mode`의 범위, ㅏ와 1처럼 비슷한 모양이 섞이지 않게) |
| `{"type":"pause"}` / `{"type":"resume"}` / `{"type":"stop"}` | 일시정지 / 재개 / 중지 |
| `{"type":"estop"}` | 긴급 정지 |
| `{"type":"test","hand":3,"jamo":"ㄱ","angles":[…]}` | 개별 손 테스트 |
| `{"type":"praise","hand":1}` | 칭찬 동작 |
| `{"type":"system","on":true}` | 시스템 시작/정지 |

### 중앙 PC → 대시보드
| 메시지 | 뜻 |
|---|---|
| `{"type":"hand_status","hand":1,"connected":true}` | 손 연결 상태 (접속 직후 5대 모두 보내 주세요) |
| `{"type":"step","i":0,"jamo":"ㅅ","hand":1,"state":"start"}` | i번째 자모 동작 시작 (`state:"end"`는 끝) |
| `{"type":"done","ms":6800}` | 단어(또는 시범) 전체 끝 |
| `{"type":"paused"}` / `{"type":"resumed"}` / `{"type":"stopped","estop":false}` | 상태 변경 확인 |
| `{"type":"test_result","hand":3,"jamo":"ㄱ","ok":true,"ms":950}` | 테스트 결과 |
| `{"type":"error","hand":2,"msg":"통신 끊김"}` | 손 오류 (알림 표시) |
| `{"type":"recog","jamo":"ㄱ","prob":0.92,"ms":420}` (숫자 10은 `"10"`) | 인식 AI 결과: 인식 글자, 확신도, 반응 시간 |

## 나중에 할 것
- 각도표는 아직 초안(확인됨 0/41)입니다. 이기태 님 확정본을 받으면 `npm run angles`로 반영합니다.
- 손으로 못 내는 글자의 영상·사진은 `public/jamo/<글자>.mp4`(먼저) 또는 `.png`로 넣으면 팝업에 나옵니다. 아직 파일이 없어 글자만 크게 보여 줍니다. 책 사진처럼 팀 내부 자료는 올리지 마세요.
- 기록·설정은 브라우저(localStorage)에만 저장됩니다. 팀 공유가 필요하면 Supabase로 옮깁니다.
- 아이콘은 Iconify 서버에서 받아 옵니다(인터넷 필요).
- 3차: 맞히기 화면(S-04), 사용자별 학습 리포트.

폴더 구조: `src/lib`(자모 분해, 통신, 상태, 통계), `src/components`(카드·그래프·손 카드·사이드바), `src/pages`(화면 6개).
